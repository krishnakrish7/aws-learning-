Security Groups vs NACLs
Most tested VPC topic. One wrong word costs you the mark.
#1 Exam Trap
🔒 Security Group
✅
Stateful — return traffic automatically allowed
✅
Applied at EC2 instance (ENI) level
✅
Allow rules only — cannot deny
✅
Evaluates all rules together
✅
Default: deny all inbound, allow all outbound
Use when: controlling access to specific EC2 instances
🚧 NACL
⚠️
Stateless — must allow BOTH inbound AND outbound
⚠️
Applied at subnet level
⚠️
Allow AND Deny rules — can block IPs
⚠️
Rules evaluated in order (lowest # first)
⚠️
Default NACL: allows all. Custom NACL: denies all
Use when: blocking a specific IP address from a subnet
⚠️ The Stateless Trap — Most Missed Question
The scenario
EC2 can receive requests but responses never get back to clients. NACL is suspected.
Why it happens
NACL allows inbound port 80 but blocks outbound ephemeral ports (1024–65535). Return traffic is blocked.
The fix
Add outbound NACL rule allowing ephemeral ports 1024–65535. Security Groups would handle this automatically (stateful).

NAT Gateway vs NAT Instance
Allows private subnet resources to access internet outbound — without being reachable inbound.
Private → Internet
⭐ NAT Gateway (Managed)
✅
AWS fully managed — no patching
✅
Highly available within AZ automatically
✅
Scales up to 45 Gbps automatically
✅
Lives in public subnet
❌
Cannot be used as bastion host
⚠️
Create one per AZ for full HA
Exam default choice — almost always correct
NAT Instance (Self-managed EC2)
⚠️
You manage patching, scaling, HA yourself
⚠️
Single point of failure unless you add HA
⚠️
Must disable source/destination check
✅
Can be used as bastion host
✅
Cheaper for very low traffic
Choose only if: "bastion host" or "cheapest possible"
NAT Gateway lives in PUBLIC subnet
Private subnet route table → NAT Gateway
One NAT Gateway per AZ for full HA
NAT Gateway ≠ Internet Gateway (different things!)

VPC Connectivity Options
Peering vs Transit Gateway vs Endpoints — three very different solutions.
Connectivity
🔗 VPC Peering
Direct 1-to-1 connection between 2 VPCs
Works across regions and accounts
NOT transitive — A↔B↔C ≠ A↔C
No overlapping CIDR blocks
Must update route tables in both VPCs
Best for: 2–3 VPCs, simple setup
🌐 Transit Gateway
Hub-and-spoke — all VPCs connect to TGW
Transitive routing supported
Works across accounts and regions
Connects VPCs + VPN + Direct Connect
10 VPCs = 10 connections (not 45!)
Best for: many VPCs + on-premises centrally
📍 VPC Endpoints
Access AWS services without internet
Gateway Endpoint: FREE, S3 + DynamoDB only
Interface Endpoint: paid, most other services
Traffic stays on AWS private network
No NAT Gateway or IGW needed
Best for: private access to S3, DynamoDB, SSM
🟢 Gateway Endpoint — FREE
✅
S3 and DynamoDB only
✅
Added to route table (not an ENI)
✅
No cost per hour or per GB
Memory: Gateway = Gratuitous (free) = S3 + DynamoDB
🔵 Interface Endpoint — Paid
⚠️
Most other services: SSM, KMS, SNS, SQS, API GW...
⚠️
Creates an ENI in your subnet
⚠️
Charged per hour + per GB of data
Use when: private access to any non-S3/DynamoDB service

VPN vs Direct Connect
Both connect on-premises to AWS. Speed vs cost vs reliability trade-off.
On-Premises → AWS
🔐 Site-to-Site VPN
✅
Encrypted tunnel over public internet
✅
Quick setup — minutes to hours
✅
Cheaper
⚠️
Reliability depends on internet quality
⚠️
Variable latency
📌
Uses Virtual Private Gateway (AWS side) + Customer Gateway (on-prem)
Trigger: "quick", "encrypted", "low cost", "internet-based"
⚡ Direct Connect (DX)
✅
Private physical connection — not over internet
✅
Consistent, low latency performance
✅
High bandwidth — up to 100 Gbps
⚠️
Takes weeks to months to provision
⚠️
More expensive
⚠️
Not encrypted by default — add VPN over DX for encryption
Trigger: "consistent", "private", "high bandwidth", "compliance"
DX + VPN backup = most resilient hybrid setup
Direct Connect NOT encrypted by default!
Add VPN over Direct Connect for encryption + private link

🎯 Exam Scenario Quick-Fire
Scenario 1
"Private EC2 needs to download OS patches from internet"
→ NAT Gateway in public subnet
Scenario 2
"Block a specific malicious IP from reaching the subnet"
→ NACL deny rule
Scenario 3
"EC2 receives traffic but responses never return — NACL involved"
→ Add NACL outbound rule for ephemeral ports 1024–65535
Scenario 4
"Private EC2 needs to access S3 without going over internet — cheapest"
→ Gateway Endpoint (free)
Scenario 5
"Connect 3 VPCs — VPC A needs to talk to VPC C through VPC B"
→ Transit Gateway (VPC Peering not transitive)
Scenario 6
"Need to connect on-premises to AWS quickly and cheaply"
→ Site-to-Site VPN
Scenario 7
"Need consistent low latency private connection from data centre to AWS"
→ Direct Connect
Scenario 8
"Direct Connect is set up but needs encryption for compliance"
→ VPN over Direct Connect
Scenario 9
"Private Lambda needs to call SSM Parameter Store privately"
→ Interface Endpoint for SSM
