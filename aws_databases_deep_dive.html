⚠️ #1 Exam Trap — Multi-AZ vs Read Replica
🛡️ Multi-AZ — AVAILABILITY
✅
Synchronous replication to standby
✅
Automatic failover (1–2 min)
✅
Backups taken from standby
❌
Standby CANNOT be read — only for failover
❌
Does NOT improve read performance
Use when: "survive AZ failure" / "automatic failover" / "HA"
📖 Read Replica — PERFORMANCE
✅
Asynchronous replication
✅
Replicas CAN be read — offload traffic
✅
Up to 5 replicas (15 for Aurora)
✅
Can be in different region
⚠️
Can be promoted to standalone DB
Use when: "read traffic" / "analytics" / "reporting overload"
⚠️ Keyword → Answer — Never Confuse These
"survive AZ failure automatically"→ Multi-AZ
"overwhelmed with read/analytics queries"→ Read Replica
"need both HA and read performance"→ Multi-AZ + Read Replica
"Lambda connecting to RDS — too many connections"→ RDS Proxy
"point-in-time recovery"→ Automated Backups
RDS Proxy = Lambda + RDS connection pooling
Automated backups → 5-min point-in-time recovery
Manual snapshots → kept until YOU delete them
Storage Auto Scaling → set max threshold, AWS handles rest

Aurora — AWS-Native High Performance DB
5x faster than MySQL RDS. Auto-scales to 128TB. 6 copies across 3 AZs.
SQL • High Performance
🚀 Aurora vs RDS
⚡
5x faster than MySQL, 3x faster than Postgres
📦
Auto-scales storage 10GB → 128TB
🔄
6 copies across 3 AZs automatically
⏱️
Failover in <30 seconds (RDS = 1–2 min)
📖
Up to 15 read replicas (RDS = 5)
💰
More expensive than RDS
🌍 Aurora Global Database
✅
1 primary + up to 5 secondary regions
✅
Replication lag <1 second across regions
✅
Promote secondary in <1 minute if primary fails
✅
Aurora Serverless — scales to zero, pay per second
✅
Writer Endpoint → primary | Reader Endpoint → replicas
⚠️
Serverless = cold start latency (not for steady traffic)
Failover <30s → Aurora. Failover 1–2min → RDS Multi-AZ
Aurora Serverless = infrequent / unpredictable workloads
Aurora Global = cross-region DR with <1s replication
⚡
DynamoDB — Serverless NoSQL
Key-value + document. Millisecond reads. Infinite scale. No servers to manage.
NoSQL • Serverless
📖 Read Consistency
Eventually Consistent — default, cheaper (0.5 RCU), may be slightly stale
Strongly Consistent — always fresh, costs 1 RCU, set ConsistentRead=true
⚡ Capacity Modes
Provisioned — set RCU/WCU manually. Cheaper for predictable load.
On-Demand — pay per request, auto-scales. Better for unpredictable.
🌍 Global Tables
Multi-region, multi-active — any region can read AND write
Async replication — eventually consistent across regions
📡 DynamoDB Streams
Captures INSERT, UPDATE, DELETE changes in order
24hr retention. Trigger Lambda on data changes.
🗂️ Indexes
LSI — must create at table creation. Same partition key.
GSI — add any time. Different partition + sort key.
⏰ TTL + DAX
TTL — auto-delete items after timestamp. Free.
DAX — microsecond reads. No code changes. Read-heavy only.
GSI = flexible, add anytime  |  LSI = must plan at creation
Streams → Lambda = event-driven architecture on data changes
TTL = free auto-deletion, great for sessions and temp data

Specialised Databases — One Liner Each
Know the trigger word for each. 1–2 questions each on the exam.
Special Purpose
🕸️
Neptune
Graph database. Stores nodes and relationships. Social networks, fraud detection, recommendation engines.
graph • relationships • social network
📒
QLDB
Quantum Ledger Database. Immutable, cryptographically verifiable transaction log. Cannot alter history.
immutable • cryptographic • audit trail
📈
Timestream
Time series database. Optimised for timestamped data. IoT sensors, app metrics, clickstreams.
time series • IoT • sensor data
📄
DocumentDB
MongoDB-compatible managed document database. JSON documents, flexible schema.
MongoDB • JSON documents
🗂️
Keyspaces
Apache Cassandra-compatible managed wide-column store. Migrate Cassandra workloads to AWS.
Cassandra • wide-column
🏭
Redshift
Data warehouse for OLAP. Columnar storage, MPP. Petabyte-scale analytics. Not for transactions.
data warehouse • OLAP • petabyte analytics
