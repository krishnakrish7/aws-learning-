📌 CNAME vs Alias — #1 Exam Trap
ALIAS ⭐
Use at ROOT domain (example.com)
✅ Works at zone apex (example.com)
✅ Free for AWS resources
✅ Supports health checks
✅ Points to: ALB, CloudFront, S3, API GW
❌ Cannot point to EC2 DNS name
CNAME
Use at SUBDOMAINS only (www.example.com)
❌ Cannot use at zone apex (example.com)
⚠️ Costs money per DNS query
❌ No health check support
✅ Can point to any domain name
✅ Works for non-AWS resources
🔀 6 Routing Policies — Know All Cold
1. Simple
One resource. No health checks. Multiple values → client picks randomly.
Single resource, no routing logic
2. Weighted
Send X% to resource A, Y% to resource B. A/B testing. Gradual deployments.
A/B test • 90/10 traffic split
3. Latency-Based
Routes to AWS region with LOWEST latency for that user. About speed, not location.
Fastest • lowest latency • best performance
4. Failover
Active-Passive. Primary gets all traffic. Health check fails → routes to secondary.
Disaster recovery • primary/secondary
5. Geolocation
Routes based on WHERE user IS geographically. Country or continent. Compliance/localisation.
User's country • language • legal region
6. Multi-Value
Returns up to 8 healthy IPs. Like Simple but WITH health checks. Client-side LB.
Multiple healthy endpoints • not a substitute for ELB
⚠️ Most Confused Pair — Geolocation vs Latency-Based
Keywords → Geolocation
"user's country / continent"
"language-specific content"
"compliance / legal restrictions"
"users in Europe see EU content"
Keywords → Latency-Based
"fastest response" / "lowest latency"
"best performance for global users"
"route to nearest region automatically"
"reduce response time globally"
Health checks → Failover routing for automatic DR
Weighted + 0 weight = remove traffic without deleting record
Always create default record for Geolocation routing

🛡️ CloudFront Security Features
🌍 Geo Restriction
Block entire countries from accessing your CloudFront distribution. Allow-list or block-list approach.
Block a country entirely
🔗 Signed URL
Grants access to ONE specific file. Has expiry time. Used for paid/premium individual content.
One file • paid download
🍪 Signed Cookie
Grants access to MULTIPLE files. Premium membership accessing entire library of content.
Multiple files • subscription
⚠️ CloudFront vs Global Accelerator — Most Confused Pair
⚡ CloudFront (CDN)
✅
Caches content at edge locations
✅
HTTP/HTTPS only
✅
400+ edge locations globally
❌
No static IP (DNS name only)
❌
Not for TCP/UDP non-HTTP
Trigger: cache • CDN • static content • HTTP • S3 website
🌐 Global Accelerator
✅
Routes through AWS private network
✅
Any protocol — TCP, UDP, HTTP
✅
2 static Anycast IPs — never change
✅
Failover in under 30 seconds
❌
Does NOT cache content
Trigger: static IP • TCP/UDP • gaming • IoT • non-HTTP
TTL = how long content is cached (default 24hrs)
Cache invalidation = force refresh before TTL expires (costs money)
Signed URL = 1 file  |  Signed Cookie = many files

🎯 Exam Scenario Quick-Fire
Scenario 1
"Send 10% of traffic to new app version, 90% to old"
→ Weighted Routing (10/90 weights)
Scenario 2
"Route Singapore users to whichever AWS region responds fastest"
→ Latency-Based Routing
Scenario 3
"Show EU users EU content, US users US content for compliance"
→ Geolocation Routing
Scenario 4
"Point root domain example.com to an ALB"
→ Alias Record (not CNAME)
Scenario 5
"Primary region fails — automatically route to DR region"
→ Route 53 Failover Routing + Health Check
Scenario 6
"Users bypass CloudFront and access S3 directly"
→ Make S3 private + Origin Access Control (OAC)

"Paid video streaming — grant access to single video file with expiry"
→ CloudFront Signed URL

"Premium membership accessing entire library of content privately"
→ CloudFront Signed Cookie

→ Global Accelerator
